# Summary
The core infrastructure for Daedalus must establish a secure, multi‑tenant, cloud‑native foundation that supports modules, integrations, permissions, and tenant isolation as reflected in your data model (e.g., tenants, modules, integrations, tenant_integrations, permissions, roles, users). The setup includes four pillars: Cloud Environment, Networking & Security, Platform Services, and Operational Foundations.

1. Cloud Environment Foundation
Azure Subscription Layout
- One primary subscription for Daedalus SaaS.
- Optional segmented subscriptions for staging, QA, and sandbox environments.
- Enforce Azure Landing Zone principles (management groups, policy, RBAC).

Resource Organization
- Resource groups per environment: rg-daedalus-core-prod, rg-daedalus-core-staging, rg-daedalus-core-dev
- Tagging standards: tenant, environment, owner, costCenter.

2. Networking & Security Architecture
Virtual Network Topology
- Hub‑and‑spoke model:
-- Hub VNet: shared services (Azure Firewall, Bastion, Private DNS).
-- Spoke VNets: application workloads (APIs, workers, integrations).

- Network Security Controls
-- Azure Firewall + NSGs for east‑west and north‑south traffic.
-- Private Endpoints for all PaaS services (SQL, Storage, Key Vault).
-- Zero Trust enforcement: identity‑based access, no public ingress.

- Identity & Access
-- Azure AD for all service identities.
-- Managed Identities for API, workers, integration services.
-- RBAC aligned with Daedalus data model roles (e.g., role_permissions, user_roles).

3. Platform Services (Core Runtime)
Compute Layer
- Azure App Service or Azure Container Apps for Control Panel API + UI.
- Background processing via Azure Functions or Container Apps Jobs.

Database Layer
- Azure SQL Database (Elastic Pool recommended for multi‑tenant workloads).
- Schema aligns with your uploaded model: tenants, tenant_modules, tenant_integrations, permissions, roles, users, system_events, billing_plans, tenant_subscriptions.
- Use Always Encrypted for sensitive fields (e.g., integration_secrets.value).

Storage Layer
- Azure Blob Storage for logs, exports, attachments.
- Azure Files for shared runtime artifacts (optional).

Secrets & Configuration
- Azure Key Vault for integration secrets (integration_secrets table reflects this need).
- App Configuration for module settings (module_settings).

4. Operational Foundations
Monitoring & Observability
- Azure Monitor + Application Insights for distributed tracing.
- Log Analytics workspace shared across environments.
- Custom events mapped to system_events table.

CI/CD Pipeline
- GitHub Actions or Azure DevOps Pipelines.
- Multi‑stage YAML pipelines: build → test → security scan → deploy.
- Infrastructure-as-Code via Bicep or Terraform.

Compliance & Governance
- Azure Policy for mandatory encryption, private endpoints, and tagging.
- Defender for Cloud for posture management.
- Backup policies for SQL, Storage, and Key Vault.
