# Non-Functional Requirements

## Performance and scale

- Gateway and services meet agreed endpoint budgets; establish P95 targets per endpoint during load testing rather than assuming one target for every flow.
- Shell static assets are CDN-cacheable; tenant-sensitive API responses are authorization- and tenant-scoped.
- Stateless services scale horizontally. PostgreSQL Flexible Server scales vertically/read replicas only when measured demand requires them; service-owned schemas remain isolated.
- Long-running booking, scheduling, job, payment, and notification work is asynchronous through Azure Service Bus.

## Availability and resilience

Production PostgreSQL uses zone-redundant HA and backups appropriate to RPO/RTO. Service Bus queues/topics use retries and dead-lettering. APIs use timeouts, circuit breakers, and safe idempotent retries. Consumers tolerate duplicate delivery and restart without losing durable work.

## Security and tenant isolation

Auth issues JWTs; Gateway validates them; every service enforces tenant/resource authorization. PostgreSQL uses `tenant_id`; API/event contracts use `tenantId`. No cross-service table access is permitted. Secret values are in Key Vault, never PostgreSQL, logs, events, or responses.

## Observability

Every request and event carries `correlationId`. Services emit structured JSON logs, request/dependency metrics, queue depth and age, database timing, and distributed traces to Azure Monitor/Application Insights. Alerts cover authentication failures, authorization denials, error rate, latency, backlog, dead letters, and payment/notification delivery failures.

## Maintainability and delivery

APIs and events are versioned, documented, backward compatible during rollout, and tested with consumer contracts. CI/CD runs tests, schema checks, security scanning, and IaC policy validation. Deployments support rolling/canary strategies and rollback without violating data ownership.
