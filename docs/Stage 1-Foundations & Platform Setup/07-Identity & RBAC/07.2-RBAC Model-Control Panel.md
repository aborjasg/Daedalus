# RBAC Model — Role-Based Access Control with Optional ABAC Extensions

## RBAC as the core model, with ABAC overlays for enterprise features.
RBAC handles:
- Module access
- Tenant administration
- Workflow editing/running
- Integration management

ABAC handles:
- “User can edit only workflows they created”
- “Support engineers can only view assigned tenants”
- “Billing managers can only view invoices for their region”

## Why this is the right choice:
- RBAC is simple, predictable, and aligns with your DB schema
- ABAC gives you enterprise flexibility without complicating the core model
- You avoid the complexity of full policy engines like OPA for all tenants

Avoid:
- Pure ABAC (too complex for most customers)
- ACLs per resource (too granular, hard to maintain)
