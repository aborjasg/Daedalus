# Core Infrastructure Setup

## Azure foundation

Use separate resource groups and deployment scopes per environment, with management-group policy, least-privilege RBAC, and tags for environment, owner, and cost center. Production workloads use private networking, Azure Firewall/NSGs, private DNS, and managed identities.

## Runtime and entry point

Host the presentation-only Control Panel Shell and private services on the selected Azure compute platform (for example Container Apps or App Service). Only the API Gateway has public ingress. Background work runs in service workers/jobs.

## Data and messaging

Use Azure Database for PostgreSQL Flexible Server as the relational platform with service-owned schemas (`auth`, `customers`, `bookings`, `scheduling`, `jobs`, `payments`, `notifications`). A separate database per service is not required initially. Use Azure Service Bus as the default queues/topics technology for commands and events, with retries and dead-letter queues.

## Secrets and operations

Use Azure Key Vault for integration secret values, signing material, and connection secrets. PostgreSQL stores only Key Vault references and metadata. Azure Monitor/Application Insights provides logs, metrics, traces, and alerts. Blob Storage may hold exports/attachments; it is not a domain database.

CI/CD runs build, tests, contract validation, security scans, IaC policy checks, and staged deployment. Backups, HA, retention, RPO/RTO, and DR replication are configured per environment.
