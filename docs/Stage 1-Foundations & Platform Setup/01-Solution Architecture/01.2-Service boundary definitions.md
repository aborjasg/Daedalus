# Service Boundary Definitions

Boundaries are defined by data ownership and business responsibility. APIs and Azure Service Bus events are the only cross-service contracts. The Shell is not a service boundary or business-logic layer.

## Services

| Service | Owns | Does not own |
|---|---|---|
| Auth | users, credentials/identity, roles, permissions, JWT issuance, authentication sessions | customer, booking, job, payment, or notification records; resource authorization decisions for other domains |
| Customers | customer profiles, contacts, addresses, customer status | authentication, bookings, schedules, jobs, payments, or messages |
| Bookings | booking requests, lifecycle/status, requested service details, booking references | availability/assignment, execution, payment settlement, or delivery |
| Scheduling | availability, assignment, calendar commitments, schedule conflicts | booking ownership, job execution, payment, or notification delivery |
| Jobs | operational jobs, checklists, execution status, completion evidence | booking creation, scheduling policy, payment processing, or authentication |
| Payments | payment intents, transactions, refunds, reconciliation, provider references | customer master data, booking status, or notification content |
| Notifications | templates, notification requests, delivery attempts/status, channel preferences | domain records and payment credentials |

## Ownership rules

- Every tenant-scoped table contains `tenant_id`; tenant context is taken from the validated JWT and never trusted from an arbitrary body field.
- A service may cache another service's published facts, but the cache is not authoritative and is updated via events.
- No service accesses another service's tables, even when schemas share one PostgreSQL server.
- The Shell calls the Gateway only and receives view data through APIs. It has no database credentials and does not subscribe directly to Service Bus.
- Integration secret values live in Azure Key Vault. PostgreSQL stores a Key Vault reference, provider metadata, and rotation/status information.

## Authorization

Auth issues JWTs. The Gateway validates signature, issuer, audience, expiry, and correlation context. Each service then enforces tenant and resource authorization for its own operations; Gateway checks are not a substitute for service authorization.
