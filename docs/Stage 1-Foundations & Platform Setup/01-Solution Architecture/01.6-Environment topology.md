# Environment Topology

Daedalus uses isolated Local, Dev, Test/QA, Staging, and Production environments; an optional DR region mirrors Production. Each environment has separate deployment scope, PostgreSQL Flexible Server, Service Bus namespace, Key Vault, identities, and monitoring boundaries.

- **Local:** containers or emulators, synthetic data, developer-scoped secrets; no production integrations.
- **Dev:** shared integration environment with synthetic tenant/customer/booking data.
- **Test/QA:** repeatable contract, integration, security, and performance tests.
- **Staging:** production-like topology and release-candidate validation; no production data.
- **Production:** restricted access, private networking, backups, HA PostgreSQL, monitored Service Bus, and approved deployments.
- **DR (optional):** replicated configuration/data according to documented RPO/RTO and exercised through drills.

The deployment path is Local → Dev → Test/QA → Staging → Production. Environment configuration is externalized; integration secret values are stored in the environment's Key Vault and referenced from PostgreSQL. No environment shares databases, message namespaces, or secret stores with another environment.
