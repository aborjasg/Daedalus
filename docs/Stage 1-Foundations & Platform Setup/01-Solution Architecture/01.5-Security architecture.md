# Security Architecture

Daedalus applies zero trust, defense in depth, least privilege, and tenant isolation.

## Identity and authorization

Auth is the authoritative authentication service and issues short-lived, signed JWTs. The Gateway validates each token before routing. Every service validates the trusted identity context and enforces tenant and resource authorization for its own data. A valid token alone never grants access to another tenant or resource. Roles and permissions are managed by Auth; domain services own domain-specific authorization rules.

## Network and data protection

Only the Gateway is public. Services, PostgreSQL Flexible Server, Service Bus, and Key Vault use private networking where supported, managed identities, and TLS in transit. PostgreSQL Flexible Server encrypts data at rest; service-owned schemas and tenant predicates/RLS provide defense against cross-tenant access.

## Secrets

Integration secret values, signing keys, and connection credentials are stored in Azure Key Vault and accessed with managed identity and least-privilege policies. PostgreSQL stores only a Key Vault reference, provider/key metadata, rotation status, and timestamps. Secrets never appear in API responses, events, logs, or source control.

## Messaging and operations

Service Bus uses Entra authentication, authorization per queue/topic, TLS, schema validation, idempotent consumers, and dead-letter handling. Structured logs redact tokens, secret values, and sensitive payloads. Correlation IDs connect Gateway requests, service spans, database operations, and events. Security events and administrative actions are auditable through Azure Monitor and service audit records.
