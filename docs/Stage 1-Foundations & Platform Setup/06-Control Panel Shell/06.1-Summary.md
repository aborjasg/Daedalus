# Control Panel Shell Summary

The Control Panel Shell is a presentation-only web application. It owns layout, navigation, tenant context display, client-side form/view state, and accessibility. It does not own business rules, domain persistence, service credentials, or event subscriptions.

All data access goes through the API Gateway, the sole external entry point. The Shell sends the JWT and correlation context to Gateway endpoints; services, not the Shell, enforce tenant/resource authorization. The Shell never connects to PostgreSQL, reads service tables, calls private services directly, or reads Key Vault.

The Shell composes views for customers, bookings, schedules, jobs, payments, notifications, and Auth-managed administration. Long-running state is displayed by polling or Gateway-mediated status endpoints. Domain events remain internal to services and Azure Service Bus.

# Control Panel Shell Summary

The Control Panel Shell is a presentation-only web application. It owns layout, navigation, tenant context display, client-side form/view state, and accessibility. It does not own business rules, domain persistence, service credentials, or event subscriptions.

All data access goes through the API Gateway, the sole external entry point. The Shell sends the JWT and correlation context to Gateway endpoints; services, not the Shell, enforce tenant/resource authorization. The Shell never connects to PostgreSQL, reads service tables, calls private services directly, or reads Key Vault.

The Shell composes views for customers, bookings, schedules, jobs, payments, notifications, and Auth-managed administration. Long-running state is displayed by polling or Gateway-mediated status endpoints. Domain events remain internal to services and Azure Service Bus.

🏛️ Architectural Role of the Shell
1. Shell as the Host Application
The shell is the Admin Web App that wraps:
- Navigation framework
- Authentication & session management
- Tenant selector
- Module loader
- Integration manager
- Settings & configuration pages
- Audit & system events viewer

It provides the consistent frame around all module content.

2. Shell as the Multi‑Tenant Boundary
The shell enforces tenant isolation:
- Loads tenant metadata from tenants
- Determines active modules from tenant_modules
- Determines plan restrictions from tenant_plans
- Applies permissions from role_permissions
- Loads tenant integrations from tenant_integrations

This ensures each company sees only what they are allowed to see.

3. Shell as the Configuration Orchestrator
The shell coordinates configuration across:
- modules
- module_settings
- integrations
- integration_secrets
- usage_metrics

It provides the UI for editing configuration and the API calls to persist it.

🧱 Shell Components (Expanded)
A. Navigation Layer
- Dynamic menu based on enabled modules
- Tenant‑aware routing
- Role‑based visibility
- Integration‑aware menu items

B. Module Loader
- Loads module metadata from modules
- Checks tenant access via tenant_modules
- Loads module settings via module_settings
- Injects module pages into the shell frame

C. Integration Manager
- Lists available integrations
- Shows tenant‑enabled integrations
- Stores secrets in integration_secrets
- Tracks usage in usage_metrics
- Provides connection status

D. Tenant Context Engine
- Loads tenant profile (tenants)
- Loads subscription (tenant_subscriptions)
- Loads plan (tenant_plans)
- Applies plan restrictions
- Applies timezone, locale, branding

E. Permissions Engine
- Loads roles (roles)
- Loads role permissions (role_permissions)
- Applies user roles (user_roles)
- Enforces module‑level and page‑level access

F. System Events & Audit
- Logs shell actions into system_events
- Tracks configuration changes
- Tracks integration failures
- Tracks module usage

🔄 Shell Lifecycle (Request Flow)
User logs in
- Shell loads user → roles → permissions
- Shell loads tenant context

Shell loads tenant modules
- Reads tenant_modules
- Filters by plan & permissions

Shell loads integrations
- Reads tenant_integrations
- Loads secrets if needed
- Checks integration status

Shell renders navigation
- Modules
- Integrations
- Settings
- System events

User interacts with module
- Shell routes to microservices
- Applies module settings
- Logs usage metrics

Shell logs events
- Writes to system_events
