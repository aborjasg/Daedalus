# Control Panel Shell API Contract

## Access and envelope

Base path: `/api/v1`. The Shell calls the API Gateway only and sends a short-lived JWT issued by Auth. Every response uses:

```json
{"success":true,"data":{},"errors":[],"correlationId":"corr-123"}
```

Each error item has `code`, `message`, and `details`. API and event tenant fields use `tenantId`; PostgreSQL uses `tenant_id`.

## Gateway routes

- `/auth/*` — sign-in/session and current identity (Auth)
- `/customers/*` — customer search, profile, and lifecycle (Customers)
- `/bookings/*` — booking creation and status (Bookings)
- `/scheduling/*` — availability and assignment (Scheduling)
- `/jobs/*` — job execution and completion (Jobs)
- `/payments/*` — payment status, refunds, and reconciliation views (Payments)
- `/notifications/*` — templates, delivery status, and preferences (Notifications)

The Shell may submit an integration connection request through the owning API. Credential values are written to Azure Key Vault by the service; the response contains only connection status and a reference-safe identifier.

## Presentation contract

Endpoints return view DTOs sufficient for rendering and may aggregate read data through the Gateway. They do not expose database schemas, secret values, internal event payloads, or cross-tenant records. The Shell must treat asynchronous operations as state transitions and render the status returned by APIs.
