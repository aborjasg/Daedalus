# Database Model: Entities and Domains

PostgreSQL Flexible Server is the relational platform. It initially hosts service-owned schemas; a separate database per service is not required. The following ownership is authoritative:

- `auth`: users, tenant memberships, roles, permissions, role assignments, authentication/audit metadata.
- `customers`: customer profiles, contacts, addresses, customer status.
- `bookings`: bookings, requested services, booking status, booking references.
- `scheduling`: availability, assignments, calendar commitments, conflicts.
- `jobs`: jobs, checklists, execution evidence, completion status.
- `payments`: payment intents, transactions, refunds, reconciliation, provider references.
- `notifications`: templates, notification requests, delivery attempts/status, channel preferences.

Tenant-scoped tables use `tenant_id` (snake case). Foreign keys to another service's record are opaque IDs/references; they are not cross-schema joins. Services resolve current data through APIs or consume events. Integration secret values are not stored in PostgreSQL: the database stores a `key_vault_secret_reference`, provider metadata, status, and rotation timestamps.

Common columns include service-owned primary key, `tenant_id` where applicable, `created_at`, `updated_at`, and optimistic-concurrency/version fields. Audit records identify actor, action, resource type/id, and correlation ID without storing secrets.
