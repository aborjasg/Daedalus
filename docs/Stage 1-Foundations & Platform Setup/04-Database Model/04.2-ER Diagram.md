# ER Diagram (Logical, Service-Owned)

```text
AUTH schema
TENANTS 1──N TENANT_MEMBERSHIPS N──1 USERS
USERS N──N ROLES (USER_ROLES) N──N PERMISSIONS (ROLE_PERMISSIONS)

CUSTOMERS schema
TENANT 1──N CUSTOMERS 1──N CONTACTS / ADDRESSES

BOOKINGS schema
CUSTOMER_REF 1──N BOOKINGS

SCHEDULING schema
BOOKING_REF 1──N ASSIGNMENTS

JOBS schema
BOOKING_REF 1──N JOBS 1──N CHECKLIST_ITEMS / EVIDENCE

QUOTE schema
TENANT 1──N PRICING_RULE_SETS
TENANT 1──N QUOTES 1──N QUOTE_LINE_ITEMS

PAYMENTS schema
BOOKING_OR_JOB_REF 1──N PAYMENT_INTENTS 1──N TRANSACTIONS / REFUNDS

NOTIFICATIONS schema
TENANT 1──N TEMPLATES 1──N NOTIFICATION_REQUESTS 1──N DELIVERY_ATTEMPTS

BOOKINGS stores accepted quote reference and price snapshot
```

The accepted quote reference in Bookings and the quote record in Quote Estimator are opaque cross-service IDs; they are not foreign keys or joins across service-owned tables. Quote Estimator owns estimate and pricing-rule data; Bookings owns the booking and accepted-price snapshot. Every tenant-scoped entity carries `tenant_id`; APIs and event envelopes expose `tenantId`.
