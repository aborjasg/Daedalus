# System Flows

## API request flow

Shell → API Gateway → JWT validation and policy → owning service → service-owned PostgreSQL schema → optional Service Bus event → Gateway envelope → Shell. The Gateway is the only external entry point. Each hop propagates `correlationId`; each service enforces tenant/resource authorization.

## Booking and scheduling flow

`BookingCreated` is published after Bookings commits. Scheduling consumes it idempotently, checks tenant-scoped availability, persists an assignment, and publishes the result. Notifications consumes the result. Failures retry with backoff and then dead-letter; the Shell displays status through APIs.

## Job and payment flow

Jobs commits completion and publishes `JobCompleted`. Payments consumes it, resolves provider secrets via Key Vault, and publishes `PaymentSucceeded`/`PaymentFailed`. Notifications consumes the outcome. No service reads another service's tables.

## Integration secret flow

An authorized tenant administrator submits credentials over the Gateway. The owning service writes values to Key Vault, stores only the secret reference and metadata in PostgreSQL, and returns status without secret material. Rotation updates Key Vault and metadata; disconnect revokes/deletes the value according to provider policy.

## Error and recovery flow

Validate → authorize → execute → commit → publish. Validation/auth errors return structured error items. Transient failures use bounded retries and idempotency. Permanent failures are dead-lettered and alerted. All failures include `correlationId` and redact sensitive fields.
